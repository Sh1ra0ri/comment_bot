# Instagram Comment Auto-Reply Bot

Telegram-управляемый бот для автоматической отправки Private Reply в Instagram
Direct по точному совпадению ключевого слова в комментарии (без учёта регистра).
Реализовано строго по ТЗ: без fuzzy-поиска, анализа смысла, ограничения
«один пользователь — один ответ» и без веб-админки.

## Структура

```
config.py, logger.py, run.py   — конфиг, логирование, единая точка входа
db/                             — asyncpg-слой (SQL напрямую, без ORM) + миграции
bot/                            — aiogram3: FSM, клавиатуры, хендлеры (админка в Telegram)
webhook/                        — FastAPI: приём Meta webhook, OAuth callback, Meta Graph API клиент
nginx/, Dockerfile, docker-compose.yml — контейнеризация и reverse proxy
```

Бот (polling) и webhook-сервер (uvicorn) запускаются в одном процессе через
`run.py` (`asyncio.gather`), чтобы webhook мог напрямую слать уведомление в
Telegram после подключения аккаунта через OAuth.

Код проверен: все модули импортируются, миграции накатываются, и вручную
протестирована ключевая логика — идемпотентность webhook, точное совпадение
ключевого слова без учёта регистра, запрет на два одинаковых ключевых слова
на одном аккаунте, каскадное удаление привязок при удалении аккаунта без
удаления самого правила.

## Что нужно сделать вам перед запуском

### 1. Meta / Facebook App
1. Создать приложение на developers.facebook.com (тип — Business).
2. Добавить продукты **Instagram Graph API** и **Webhooks**.
3. Настроить Facebook Login for Business с redirect URI
   `https://ваш-домен/oauth/callback` — именно этот URL должен совпадать с
   `META_REDIRECT_URI` в `.env`.
4. Запросить разрешения (permissions) для приложения:
   `instagram_basic`, `instagram_manage_comments`,
   `instagram_manage_messages`, `pages_show_list`, `pages_manage_metadata`.
   Для продакшена они потребуют **App Review** от Meta — без review приложение
   будет работать только с аккаунтами, добавленными в тестовый режим (Roles →
   Testers) в самом приложении Meta.
5. Подписать приложение на Webhooks для поля `comments` на нужной странице/IG
   аккаунте, указав тот же `META_VERIFY_TOKEN`, что в `.env`.
6. У каждого Instagram-аккаунта, который будет подключаться через бота, должен
   быть тип **Business** или **Creator** и он должен быть привязан к
   Facebook-странице — иначе `instagram_business_account` не будет найден.

Важно: точные названия полей/эндпоинтов и правила review в Graph API у Meta
периодически меняются. Реализация в `webhook/meta_client.py` написана по
задокументированному на сегодня флоу (обмен code → long-lived token →
`/me/accounts` → `instagram_business_account` → Private Reply через
`/{comment-id}/private_replies`), но перед продакшен-запуском стоит сверить
её с актуальной документацией Meta for Developers на момент деплоя.

### 2. Сервер и домен
- Нужен сервер с публичным доменом и валидным HTTPS-сертификатом — Meta не
  примет webhook и OAuth redirect на голый HTTP или self-signed сертификат.
  В `nginx/nginx.conf` оставлен только HTTP-блок с комментарием — сертификат
  (например, через `certbot`) и HTTPS server-блок на 443 нужно добавить
  самостоятельно под ваш домен, либо поставить Nginx за уже существующим
  HTTPS-терминатором.
- Открыть порты 80/443 наружу.

### 3. Telegram
- Создать бота через @BotFather, получить `TELEGRAM_BOT_TOKEN`.
- Узнать свой Telegram numeric ID (например, через @userinfobot) и указать
  его в `SUPER_ADMIN_ID` — это ваш главный администратор. Он сидируется в
  БД при каждом старте приложения, не может быть удалён (в том числе самим
  собой) и не отображается с кнопкой удаления в списке администраторов.
  Остальных администраторов добавляете уже через само меню бота
  («👥 Администраторы» → «➕ Добавить администратора» — можно переслать
  сообщение от нужного человека или прислать его числовой Telegram ID).
  Без `SUPER_ADMIN_ID` никто не получит доступ к боту (middleware блокирует
  всех, кого нет в таблице `admins`).

### 4. Заполнить `.env`
Скопировать `.env.example` в `.env` и заполнить все поля:
`TELEGRAM_BOT_TOKEN`, `ADMIN_IDS`, `POSTGRES_*`/`DATABASE_URL`,
`META_APP_ID`, `META_APP_SECRET`, `META_VERIFY_TOKEN`, `META_REDIRECT_URI`.

### 5. Запуск
```bash
docker compose up -d --build
```
Миграции накатываются автоматически при старте приложения (`run_migrations()`
в `run.py`), отдельно ничего применять не нужно.

### 6. Проверка
- Написать боту `/start` — должно появиться главное меню (если ваш ID есть в
  `ADMIN_IDS`).
- Пройти цепочку «Добавить аккаунт» → ссылка авторизации → после успешного
  OAuth в чат должно прийти подтверждение.
- Проверить, что `GET https://ваш-домен/webhook?hub.mode=subscribe&hub.verify_token=...&hub.challenge=123`
  возвращает `123` — это то же самое, что Meta делает при подписке.

## Что не реализовано намеренно (по п.30 ТЗ)
Веб-админка, fuzzy/частичный поиск ключевых слов, анализ смысла комментария,
ограничение «один пользователь — один ответ», авто-подстановка ссылок в
сообщение.
